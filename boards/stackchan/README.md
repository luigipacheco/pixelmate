# PixelMate on the M5Stack StackChan

A second firmware build of PixelMate for the **M5Stack StackChan** (its head is
an M5Stack CoreS3: ESP32-S3, 320x240 touch LCD, 16 MB flash, 8 MB quad PSRAM).

It builds the same game sources as the ESP-Mosaico project in the repo root
(`../../main`, `../../components`). Only what is in this folder is Stack-chan specific:

| Path | What |
|---|---|
| `CMakeLists.txt`, `sdkconfig.defaults`, `partitions.csv` | The ESP32-S3 project |
| `components/stackchan_board/` | Board adapter (display, touch, speaker), adapted from Raylib Lite Engine's `examples/boards/esp32-s3-box-3` |
| `bmgr/m5stack_cores3/` | ESP Board Manager profile for the CoreS3, copied from `espressif/m5stack_boards` 0.6.2 (esp-board-manager commit c09d8cb); license in `bmgr/LICENSE` |
| `components/gen_bmgr_codes/` | Generated by `idf.py bmgr`; not in git |

## What is different from the Mosaico build

Bitsy is a **desk pet** here (`pixelmate_feature(DESK_PET)` in `board.cmake`,
which sets `app_game_config_t.desk`):

- No step counting. Steps reported by any source are ignored.
- Daily health is paused: no hearts lost, no fainting.
- Every 3 pats on the face earn 1 spark (`APP_DESK_PETS_PER_SPARK`).
- **Stays awake on USB power.** The body's battery monitor tells when a supply
  is connected; the screen then neither dims nor sleeps, and plugging in wakes it.
- **Clock mode.** Kept awake and left alone for 12 s on Home, Bitsy shrinks to
  the top and shows the time (12-hour, date underneath). Digits bounce in when
  the minute changes, the hour gets confetti; a tap brings the face back. The
  time comes from Wi-Fi (NTP) and is kept in the CoreS3's battery-backed clock
  chip, so it survives power-off. The timezone is set by opening the stats page
  once, as on the Mosaico.
- **Neck.** The head looks around when idle, sags when sleepy, nods, shakes
  and wiggles with the pet's events, and holds still while the screen is
  touched or a menu or game is open. Asleep, it goes home and the servos let go.

Stack-chan drivers live next to the Mosaico ones in the shared components and
are picked by this board's parts list (`board.cmake`, see `../README.md`);
boards without the hardware get do-nothing stand-ins (`*_none.c`):

| Component | Stack-chan |
|---|---|
| `app_camera_hw` | Built-in GC0308 through the Board Manager camera device: photo booth. No Wi-Fi webcam yet (no hardware JPEG). |
| `app_power_hw` | INA226 on the body (I2C 0x41): voltage, current, estimated percent, supply connected. |
| `app_neck_hw` | Two SCS0009 bus servos on UART1 (TX 6 / RX 7), rail switched by the PY32 expander (I2C 0x6F). |
| `app_rtc_hw` | BM8563 clock chip (I2C 0x51). |
| `app_pedometer_hw` | Stand-in: no step counting on a desk robot. |

Mosaico-only features that are switched off here:

- **Pocket mode** (deep sleep on battery with steps still counted). A desk
  robot is not carried, and on the Stack-chan GPIO7, the Mosaico's AI button,
  is the neck-servo line.
- **Vibe Mode Wi-Fi**: Wi-Fi comes only from the app's own SET UP WIFI hotspot.

### Neck safety and calibration

The tilt axis is easy to destroy by driving it into its stops, so the driver:

- takes hold only at the position where it finds the head (nothing jumps);
- refuses to move when the tilt is outside the calibrated band;
- clamps every write to that band and to the aim limits (pan 40, tilt 16 degrees);
- releases a servo that stops following its goal for 2 s.

Home and the tilt band are per robot. The defaults in `app_neck_hw_scs0009.c`
were measured on Luis's unit (home 512/743 ticks, tilt band 592..894); another
robot needs its own values in NVS namespace `neck` (`home_pan`, `home_tilt`,
`tilt_lo`, `tilt_hi`, all u16). There is no calibration command yet.

Not done yet:

- **Looking at faces.** `pet_head` already aims at a face when given one; the
  on-device detector (`app_face_hw`, ESP-DL) is not wired in yet.
- **Screen layout.** The game still draws its 480x480 picture; the adapter
  shrinks it to 240x240 in the middle of the 320x240 LCD with black bars left
  and right. Text and buttons are half size. A real 320x240 layout is the next
  big piece and would also make it faster.
- **Screen sleep.** The game "sleeps" by drawing black, which saves power on the
  Mosaico's AMOLED but not on this backlit LCD. The backlight needs real control.
- **Body extras**: RGB LEDs, head touch, IR, NFC.

## Build

Needs the pinned ESP-IDF (6.2) with the ESP32-S3 toolchain
(`idf_tools.py install xtensa-esp-elf`).

Once per checkout, generate the Board Manager files (run in this folder):

```
idf.py bmgr -c ./bmgr -b m5stack_cores3
```

If `idf.py` does not know `bmgr`, point `IDF_EXTRA_ACTIONS_PATH` at a
downloaded `managed_components/espressif__esp_board_manager` first.

Then build:

```
idf.py -B build -DIDF_TARGET=esp32s3 build
```

Flash over the CoreS3's USB-C port with `idf.py -B build -p <port> flash monitor`.
Flashing replaces M5Stack's factory firmware.

## Status

First run on a StackChan on 2026-11-21 (boot log over USB):

- Boots into the game; 8 MB PSRAM found; the pet's save loads from NVS.
- LCD and touch start; a tap on the dark screen woke the pet.
- Speaker starts (AW88298, 24 kHz mono) and all 27 sounds load.
- Wi-Fi starts and offers the `PIXELMATE-XXXX` setup hotspot.
- Speed: about 35 ms to draw a frame plus 39 ms to send it to the LCD, so
  roughly 13 pictures a second (the game logic still runs at 30). Drawing a
  320x240 picture instead of 480x480 is the fix.

Second run the same day, after adding the neck, clock and power code:

- Neck: rail on, both servos answer, head found at its calibrated home
  (514/743 ticks against 512/743), no stall or error; Luis confirmed it moves
  smoothly.
- Battery monitor reads about 70 %, 3.9 V, charging at ~250 mA on USB, so the
  stay-awake rule is active.
- Clock mode appears after 12 s untouched (confirmed on the robot). Drawing
  takes about 37 ms a frame with the clock showing.

Not checked yet: the camera and photo booth, whether the neck's left/right
and up/down match what the code calls them, the clock chip after a power-off,
joining Wi-Fi, and how the sound actually sounds.
